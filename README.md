# Лабораторная работа №2. Потоковый анализатор файлов

`streamstats` читает события из CSV, JSONL и TSV, подсчитывает статистику и сохраняет отчёт в JSON или CSV.

Файлы обрабатываются последовательно, без загрузки всех событий в память.

## Возможности

- Проверка обязательных полей событий.
- Подсчёт общего количества событий.
- Подсчёт событий по уровням и источникам.
- Топ-5 источников ошибок уровня ERROR и CRITICAL.
- Определение минимальной и максимальной временных меток.
- Объединение статистики нескольких файлов.
- Пропуск неверных записей с предупреждением и подсчётом пропусков.
- Ленивые фильтры по уровню, источнику и времени.
- Реестр функций парсеров.
- Сохранение отчётов в JSON и CSV без повторных расчётов.

## Формат события

Каждое событие содержит обязательные поля:

| Поле | Значение |
|---|---|
| `timestamp` | Временная метка ISO 8601 |
| `level` | DEBUG, INFO, WARNING, ERROR или CRITICAL |
| `source` | Непустая строка с названием источника |
| `message` | Строка с сообщением |

Пример JSONL-события:

```json
{"timestamp":"2026-11-10T10:00:00+03:00","level":"ERROR","source":"database","message":"Ошибка подключения"}
```

В JSONL каждое событие записывается на отдельной строке.

CSV и TSV должны содержать заголовок с названиями полей. CSV использует запятую, TSV — табуляцию.

## Запуск

Для следующих команд нужно перейти в папку `src`:

```bash
cd src
```

Анализ CSV с сохранением JSON-отчёта:

```bash
python -m streamstats analyze streamstats/events.csv --format csv --output reports.json
```

Анализ JSONL с пропуском неверных записей:

```bash
python -m streamstats analyze streamstats/events.jsonl --format jsonl --output reports.json --skip-invalid
```

Анализ TSV:

```bash
python -m streamstats analyze streamstats/events.tsv --format tsv --output reports.json --skip-invalid
```

Объединение нескольких файлов:

```bash
python -m streamstats analyze first.csv second.csv --format csv --output reports.json
```

Все входные файлы в одном запуске должны иметь указанный формат.

Сохранение статистики в CSV:

```bash
python -m streamstats analyze streamstats/events.jsonl --format jsonl --output reports.csv --report-format csv --skip-invalid
```

Повторный запуск перезаписывает выбранный файл отчёта.

Справка:

```bash
python -m streamstats --help
python -m streamstats analyze --help
```

## Параметры CLI

| Параметр | Назначение |
|---|---|
| `INPUTS` | Один или несколько входных файлов |
| `--format` | Входной формат: csv, jsonl или tsv |
| `--output` | Путь выходного отчёта |
| `--report-format` | Формат отчёта: json или csv; по умолчанию json |
| `--skip-invalid` | Пропуск неверных записей |
| `--level` | Фильтр по точному уровню |
| `--source` | Фильтр по источнику |
| `--from-time` | Начало диапазона времени включительно |
| `--to-time` | Конец диапазона времени включительно |

## Ленивые фильтры

Пример совместного отбора по уровню и источнику:

```bash
python -m streamstats analyze streamstats/events.csv --format csv --output reports.json --level ERROR --source database --skip-invalid
```

Фильтр ERROR выбирает только ERROR и не включает CRITICAL.

Пример диапазона времени:

```bash
python -m streamstats analyze streamstats/events.csv --format csv --output reports.json --from-time "2026-11-10T10:05:00+03:00" --to-time "2026-11-10T10:10:00+03:00" --skip-invalid
```

Можно указать только одну границу. При указании нескольких фильтров событие должно соответствовать всем условиям.

Для временных фильтров требуется часовой пояс. Начало диапазона не должно быть позже конца.

Фильтрация выполняется генератором: события проверяются по одному при переборе.

## Содержимое отчёта

| Поле | Описание |
|---|---|
| `total_events` | Количество обработанных событий после фильтрации |
| `skipped_invalid` | Количество неверных записей, пропущенных при чтении |
| `by_level` | Количество событий каждого уровня |
| `by_source` | Количество событий каждого источника |
| `by_error` | Количество ERROR и CRITICAL по источникам |
| `top_5` | Пять наиболее частых источников ошибок |
| `mn` | Минимальная временная метка выбранных событий |
| `mx` | Максимальная временная метка выбранных событий |

Неверные записи не участвуют в статистике. Корректные события, исключённые фильтром, не увеличивают `skipped_invalid`.

Для пустого результата количество событий равно нулю, топ пустой, а временные метки равны `null`.

CSV-отчёт содержит колонки `section`, `name`, `value`. Для его создания используется та же рассчитанная статистика, что и для JSON.

## Обработка ошибок

По умолчанию неверная запись останавливает обработку. Программа выводит путь файла, номер строки и причину, затем завершается с кодом 2.

С флагом `--skip-invalid` поддерживаемые ошибки записей приводят к предупреждению WARNING и увеличению счётчика пропусков.

Используются исключения:

- `StreamStatsError` — базовое исключение.
- `InvalidEventError` — неверное событие.
- `InvalidTimestampError` — неверная временная метка.
- `UnsupportedFormatError` — неизвестный входной формат.
- `CLIConfigError` — неверные настройки обработки.

Текущие ограничения:

- Повреждение структуры CSV, например незакрытая кавычка, останавливает чтение даже с `--skip-invalid`.
- При ошибке структуры CSV номер строки может быть неточным.
- Не следует смешивать временные метки с часовым поясом и без него: их сравнение вызывает ошибку.
- Папка для выходного отчёта должна существовать; ошибки файловой системы пока не преобразуются в исключения программы.

## Реестр парсеров

Парсеры выбираются через словарь `PARSERS`.

Получение функции:

```python
parser = get_parser("csv")
```

Регистрация дополнительного формата:

```python
register_parser("tsv", parse_tsv)
```

Зарегистрированная функция должна принимать `path`, `skip_invalid` и `stats`, а затем выдавать проверенные события.

TSV-парсер использует CSV-парсер с разделителем `"\t"`. Для подключения TSV изменение логики CLI не требуется.

## Измерение памяти

Проверка выполнена на macOS с Python 3.14.10.

Размер входного JSONL-файла: 524 900 000 байт, примерно 500,58 МиБ. Файл содержит повторяющиеся события одного источника.

Для создания аналогичного файла из папки `src`:

```bash
python - <<'PY'
import json
from pathlib import Path

path = Path("large_events.jsonl")
target = 500 * 1024 * 1024

event = {
    "timestamp": "2026-11-10T10:00:00+03:00",
    "level": "INFO",
    "source": "api",
    "message": "Событие для измерения памяти",
}

line = (json.dumps(event, ensure_ascii=False) + "\n").encode("utf-8")
chunk = line * 5000

with path.open("wb") as file:
    while file.tell() < target:
        file.write(chunk)

print(f"Размер файла: {path.stat().st_size} байт")
PY
```

Команда измерения:

```bash
/usr/bin/time -l python -m streamstats analyze large_events.jsonl --format jsonl --output reports.json 2> memory.txt
```

Полученные результаты:

| Показатель | Значение |
|---|---|
| Время выполнения (`real`) | 5,21 с |
| Пиковая резидентная память | 38 830 080 байт |
| Пиковая резидентная память в МиБ | 37,03 МиБ |
| Swaps | 0 |

Результат соответствует потоковой обработке этого набора данных: потребление памяти значительно меньше размера файла.

При увеличении количества уникальных источников память может расти, поскольку анализатор хранит их счётчики.

Большой тестовый файл не включается в репозиторий. Результат замера сохранён в `src/memory.txt`.
